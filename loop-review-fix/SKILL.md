# 迭代检视修复

## 范围与轮数

- 按用户指定范围检视；默认覆盖未提交改动及相关未跟踪文件。范围不清或无内容时先询问。
- 记录基线、需求和仓库约定；每轮覆盖原始范围及本次修复。
- 用户指定的正整数轮数优先，默认最多 50 轮；无效值先澄清。一轮包含检视、必要修复和验证，复检计入下一轮。
- 只 review 或明确不要改：仅做一次只读检视，报告意见与修复建议。

## 每轮流程

1. **检视**：读取相关文件、diff、已有 findings 和失败输出，核实正确性、需求符合性及验证缺口。默认使用 subagent 检视，提供范围、基线、需求和只读要求，等待结果。没有可用 subagent 时由当前 agent 检视；检视失败时补做或报告阻塞。
2. **确认**：意见需有位置或行为、触发条件、影响和证据。合并重复意见，对冲突或疑点做最小定向检查；仍影响修复决策时报告阻塞。偏好建议单独列出。
3. **修复**：默认使用 subagent，提供已确认的问题、证据和修改范围，等待修复结果；没有可用 subagent 时由当前 agent 修复。只改范围内有依据的问题，沿用项目模式，保留无关用户改动；范围外发现单独报告。
4. **验证**：执行仓库要求及与改动匹配的最窄检查，尽可能覆盖问题触发条件。失败时判断与本次改动的关系；无法执行时记录原因、人工复核范围和验证缺口。
5. **复检**：记录本轮结果，按停止条件决定是否继续。最后一轮有修复时仍完成验证，并标明修复后的复检未完成。

## 停止与报告

满足任一条件即停止：

- 检视完成，范围内无可修复或待确认问题。
- 达到轮数上限。
- 需要用户决策、材料或工具才能继续。
- 同一问题反复出现，且本轮无新增证据或有效修复。

最终说明结论、实际轮数 `N / MAX`（只检视时标明只读）、停止原因、检视来源、修改文件与关键修复、验证结果及剩余事项。检查结果区分通过、失败和未执行；剩余事项包含未解决问题、验证缺口、未完成的复检及所需下一步，确实为空时写“无”。
