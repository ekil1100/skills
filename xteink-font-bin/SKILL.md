# 阅星瞳 / XTEink 墨水屏字体转 bin

把 TTF/OTF 转成这类阅读器能读的 1-bit 定长点阵 `.bin` 字库。脚本已封装好全部逻辑，
正常情况下你只需要确认字号、跑脚本、用预览图验收。

## 为什么用这个脚本而不是网页转换器

社区网页工具（XTEink-Web-Font-Maker 等）量“格子宽度”时通常只测拉丁字母，遇到
“汉字 = 2×字母宽”的中文等宽字体会把汉字裁掉一半。本 skill 的脚本按**汉字实际墨迹**
测量格子，并避开了双倍高度的竖排重复符号（U+3031–3035）这类离群字形导致行高翻倍的坑。
格式细节见 `references/bin-format.md`（需要核对偏移、文件名解析、固件排版规则时再读）。

## 前置依赖

```bash
pip3 install --user freetype-py pillow
```
`freetype-py` 必装；`pillow` 仅在生成预览图（`--preview`）时需要。

## 工作流程

### 1. 确认字号

固件里**每个 bin 的字号、行距、间距是固定的**，机器上不能调，所以转换时就要定好。
墨水屏对比度低，字号通常比手机大一档。按屏幕给个起点，拿不准就一次多转几档让用户挑：

- 估算：`一行汉字数 ≈ 屏幕逻辑宽 / cellW`，`每屏行数 ≈ 屏幕逻辑高 / (cellH + 行距)`。
  阅星瞳 X4 是 480×800 逻辑分辨率、4.7 寸。
- 经验档位（X4）：28px 信息密度高、32px 小四均衡、36px 四号最舒适、40px 大字。
  常用默认：一次转 28 / 32 / 36 / 40 四档。

### 2. 跑转换脚本

```bash
python3 <skill>/scripts/ttf2xteink.py 源字体.ttf \
    --size 28 32 36 40 \
    --name MapleMonoCN \
    --out bin-fonts \
    --preview
```

- `--size` 可一次给多个字号，逐个生成。
- `--name` 是设备字体列表里显示的名字；脚本会把其中的下划线换成连字符（文件名靠
  下划线分段，名字里不能掺）。默认取源文件名。
- 笔画偏淡的墨水屏可改用 Medium/SemiBold 字重的源文件，往往比 Regular 更耐看。
- 行距太挤可加 `--line-spacing 4`；字间距加 `--char-spacing N`。

输出文件名形如 `MapleMonoCN_36_35x43.bin`——这个名字**不能随意改**，固件从中读取
字号和格子宽高。

### 3. 用预览图验收

`--preview` 会在每个 bin 旁生成同名 `.preview.png`，按固件排版逻辑（全角占满格、
半角紧排）渲染一段中英混排样张。**转完务必读一下预览图**确认：汉字没被裁、中英混排
对齐正常、行距合适。把预览图展示给用户，让他挑字号。

### 4. 导入设备

阅星瞳 X4：菜单「升级/传书」→ 手机扫码传书 / 电脑登录网址 → 上传字体 → 选刚生成的
`.bin`。把几个字号都传上去、在机器上实际看一眼最准，不喜欢的删掉即可。

## 批量字重示例

想把一个字体家族的多个字重都转好：

```bash
for f in MapleMono-NF-CN-Regular.ttf MapleMono-NF-CN-Medium.ttf; do
  python3 <skill>/scripts/ttf2xteink.py "$f" --size 32 36 --name "MapleMonoCN-${f%.ttf}" \
      --out bin-fonts --preview
done
```

## 故障排查

- **汉字被裁/只显示一半**：几乎都是用了只测拉丁字母的转换器；本脚本已按汉字墨迹测量，
  若仍出现请确认源字体确实含 CJK 字形（`get_char_index` 为 0 表示该字体没有这个字）。
- **行距异常大**：通常是离群高字形混入测量；脚本已跳过 U+3031–3035，如换了别的字体
  仍异常，按 `references/bin-format.md` 的方法定位最高字形再扩展跳过范围。
- **文件很大（十几 MB）**：定长格式的固有代价（65536 个格子，缺字也占位），属正常。
- **设备不识别字号**：检查文件名是否保持 `名字_字号_宽x高.bin` 格式、名字里没有多余下划线。
