# 阅星瞳 / XTEink 家族 .bin 字体格式

权威来源：crosspet 开源固件 `lib/ExternalFont/ExternalFont.cpp`（X4 第三方固件，
与原厂格式一致）。同格式被阅星瞳 X4、EDCBook、墨菲 3.7、武哒哒·小墨等设备共用。

## 文件结构

- 整个文件是 **65536（0x10000）个 Unicode BMP 码点**的定长点阵格子，按码点从
  0 到 0xFFFF 顺序紧密排列，没有文件头、没有索引表。
- 码点 N 的点阵起始偏移 = `N * bytesPerChar`。固件就是这样直接 seek 定位的，
  所以顺序和定长不能变。
- 字体没有的字符，对应格子保持全 0；固件检测到全 0（且非空白、非 ASCII）会按
  “缺字”处理。

## 单个格子的位图布局

- `bytesPerRow = ceil(cellWidth / 8)`
- `bytesPerChar = bytesPerRow * cellHeight`
- **行优先**：先存第 0 行的全部字节，再第 1 行……
- 每个字节 **高位(MSB)对应最左像素**；行末不足 8 位的部分用 0 补齐。
- 固件取位：`bit = (data[y*bytesPerRow + x/8] >> (7 - x%8)) & 1`，1 = 黑（着墨）。

## 文件名约定（重要）

固件**不从文件内部读尺寸**，而是从文件名解析：

```
字体名_字号_宽x高.bin
例：MapleMonoCN_36_35x43.bin  ->  size=36, cellW=35, cellH=43
```

- 解析逻辑：从右往左找最后一个 `_`，按 `%dx%d` 读宽高；再往左一个 `_` 读字号；
  剩下的是字体名（显示在设备字体列表里）。
- 因此**字体名部分不能再包含会干扰解析的下划线规律**——脚本会把名字里的 `_`
  替换成 `-`，保证只有“字号”和“宽x高”两段分隔下划线。
- `bytesPerChar` 不能超过固件的 `MAX_GLYPH_BYTES`，所以字号别给到离谱的大。

## 固件排版行为（解释为什么这样测量格子）

- **全角**字符（CJK 统一表意 0x2E80–0x9FFF、CJK 标点/假名 0x3000–0x30FF、
  兼容表意 0xF900–0xFAFF、全角符号 0xFF00–0xFF60）按 `cellWidth` 占满整格。
- **半角**字符按实际墨迹宽度 + 2px 紧排（`advanceX = 内容宽 + 2`，封顶 cellWidth）。
- 所以中英混排会自动得到“汉字定宽、英文紧凑”的正常效果，**前提是格子宽度按汉字
  墨迹测量**。如果只按拉丁字母测宽（很多网页转换器的默认行为），汉字会被裁掉一半。
- 全角到半角回退：找不到 U+FF01–FF5E 的字形时，固件会退到 U+0021–007E。

## 常见坑

- **U+3031–U+3035**（〱〲〳〴〵 竖排重复符号）是双倍高度的离群字形，若混进格子
  尺寸测量会把行高撑大近一倍。脚本已在测量范围里跳过它们。
- 文件偏大属正常：65536 × bytesPerChar，36px 中文字体约 13 MB，是定长格式的固有
  代价（缺字格子也占位）。
