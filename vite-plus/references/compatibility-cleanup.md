# 验证后清理兼容配置

仅在迁移或升级已有通过基线后执行。目的不是删除所有兼容项，而是在有证据时采用新默认值，同时保留原有行为契约。

## Vitest

1. 用迁移 diff 和 `Vitest v4 compatibility` 注释列出根、工作区及内联项目配置中新插入的候选项。读取每项注释链接及 https://viteplus.dev/guide/vitest-v5#remove-unneeded-compatibility-settings。原有用户设置和来源不明的设置保持不变。
2. 逐项检查移除后的有效值，包括继承、插件、配置合并和 setup 文件；一次只移除一个新增设置，先不改代码运行受影响项目及测试套件。涉及浏览器或覆盖率时必须验证对应套件，不能只跑 Node 测试。
3. 必要时允许少量局部应用、测试或 setup 修复，例如修正 locator 或少数 mock 初始化。保留断言意图、测试集合和覆盖率；审查快照变化，不能无审查地接受更新。需要广泛测试修改或共享 setup 重构时，暂留兼容项，记录后续工作。
4. 仅当受影响套件通过、同一测试集合仍执行且没有新增跳过时，保留移除并删除对应生成注释。验证失败、无法运行或行为仍不确定时，恢复该设置及注释；只撤销本次清理试验的修改，保留已完成迁移修复和无关工作。

特殊边界：

- `fakeTimers.toNotFake` 只移除新增的 `Temporal`，保留其他排除项。
- glob 覆盖率阈值的 `perFile: true` 保留，除非用户明确同意改为聚合检查；测试覆盖率通过不代表检查强度不变。
- `clearMocks`、共享 Vite server、内联 `extends` 和 locator 精确匹配等候选项按实际生成注释确定，不主动删除同名旧设置。

## tsdown / 库打包

仅处理使用 `vp pack` 且打包基线通过的项目。用迁移 diff 与 `tsdown <0.23 compatibility` 注释确定新增项，读取注释链接；保留用户原有配置。

- 移除 `deps.resolveDepSubpath: true` 后，外部 subpath 导入保持源码写法。检查产物导入，以及消费方对这些路径和声明的解析。参考 https://tsdown.dev/options/dependencies#deps-resolvedepsubpath。
- 移除 `attw.profile: 'strict'` 会采用 `esm-only`，跳过 node10 和 CommonJS 解析检查。如果这些检查属于库承诺的支持范围，保留 strict。不能为打包通过而丢弃预期声明检查。参考 https://tsdown.dev/options/lint#profiles。

一次移除一项及其注释，然后运行 `vp pack` 和消费方检查。失败、消费方检查无法运行或支持契约不明确时，恢复设置及注释，仅撤销对应清理试验。

## 最终验证与报告

将接受的移除合并后，再跑主文件列出的全部适用验证，包括相关工作区包、浏览器、覆盖率、基准测试、应用构建、库打包及消费方检查。若组合后失败，定位并恢复引起问题的清理项后重新验证；不能拿单项成功代替组合结果。

逐项报告：

| 配置路径与候选项 | 移除或保留 | 局部代码修改 | 验证命令及结果 | 原因与后续工作 |
| --- | --- | --- | --- | --- |

区分：已验证后接受新默认值、为支持契约保留、需要较大重写而延期、因环境或证据不足无法验证。没有生成候选项则注明不适用。
